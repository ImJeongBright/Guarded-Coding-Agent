# 001-04 — Shell Profiles and OS Sandbox

Date: 2026-10-03. Base commit: b93ba56. Policy: 001.

## Implementation

exact argv/cwd, canonical absolute executable, shell=False, clean environment,
timeout, bounded output과 macOS Seatbelt sandbox를 구현했다. 격리 실패에 fallback은 없다.
프로필마다 write_paths를 요구하고 생략 시 읽기 전용이다. 전체 workspace, 외부 및
민감 write profile은 거부한다. compiler=build, test=build/test-data, DB=data.db/data.db.tmp로 제한했다.

## Tests

SH-01~05와 `test_sandbox_edges.py` 7개, `test_write_scope.py` 3개를 전체 suite에서 통과했다.
실제 child가 실행됐는지도 assertion한 뒤 외부 read/write, secret/state, network,
runtime link escape, 환경 secret 상속, output truncation과 timeout을 검사했다.

## Observed Failures / Decisions

- 중첩 sandbox는 sandbox_apply EPERM. 별도 허용된 테스트 프로세스에서 격리 검증.
- root directory read가 없어 정상 loader가 SIGABRT. `/` 자체만 허용하고 하위 전체는 열지 않았다.
- exact argv의 문장부호도 막혔다. reviewed exact argv는 데이터로 허용, 미등록 composition/nested shell은 차단.
- Apple cc wrapper의 developer selection/cache 및 SDK 탐색이 막혔다. 실제 clang/SDK를 고정하고 좁은 system metadata를 허용.
- argv 고정만으로 source overwrite/delete가 가능했다. 실패 test 후 write_paths를 OS 격리에 적용했다.

## Limits

macOS backend만 제공한다. 반환 output stream 각 64 KB, child 파일 크기 32 MiB,
20초 기본/120초 최대다. process group 종료를 사용하지만 악성 daemon의 완전한 자원 격리는 주장하지 않는다.
등록된 artifact/data scope 내부 파괴까지 막는 것은 아니다. 시스템 라이브러리 read와 private temp write는 필요 권한이다.
