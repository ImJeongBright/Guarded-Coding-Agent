# 002-05 — 실제 모델의 C DBMS 개발

준비된 action 목록을 재생하지 않고 실제 Codex에게 작업 목표만 전달했다.
baseline에는 id 0을 거부하는 버그를 넣었다. 모델은 코드 읽기, 수정, 테스트 추가,
컴파일, Git staging/commit 순서를 직접 선택했다.

- id 0 버그 수정, `count` 명령 추가, command dispatch 함수 분리, README 갱신.
- Guard 도구 호출 20개, ALLOW 20, DENY/APPROVAL 0.
- 실제 compiler 통과, 모델이 작성한 테스트를 포함해 11개 통과.
- 별도 검증자가 Guard sandbox에서 빈 DB, id 0, 최대 id, 중복 거부, 재시작 count,
  GDB1 binary header를 다시 검사했고 모두 통과했다.
- fixture local commit `de37b9a`, working tree clean. 원본 저장소 commit/push는 하지 않았다.

검토·검증한 결과를 `examples/c-dbms`에 반영했다. 합성 001 runner도 테스트 수를
실제 unittest 결과에서 읽도록 수정했다. 원본 001의 8개 테스트 증거는 당시 기록으로 보존한다.

증거: `.guard-runs/live-c-01/session/events.jsonl`, `state/audit.jsonl`, `verification.json`.
모델의 friction 응답은 없음이었다. 이는 이 작은 C task의 관찰이며 장기 사용자 평가가 아니다.
