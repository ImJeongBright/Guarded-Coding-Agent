# 002-01 — 실제 Codex 연결

Date: 2026-10-03. macOS 15.7.8 arm64, Python 3.12.1, Codex CLI 0.160.0.

`live-smoke-01`에서 실제 모델이 Guard MCP를 호출하여 hello.txt를 읽고 proof.txt를 만들었다.
CLI는 기존 ChatGPT 로그인을 사용했다. Guard에 API client, key, HTTP server는 추가하지 않았다.

`guarded_agent/host.py`, `scripts/run_guarded_codex.py`로 전용 실행 구성을 만들었다.
사용자 전역 config/rules를 읽지 않고, ephemeral session과 별도 로그/상태를 사용한다.
native shell, 다른 MCP·앱·브라우저·이미지·추가 agent 기능을 줄이고 host는 read-only/approval never로 둔다.
Guard 서버는 required이며 세 도구만 노출한다. 코드 모드 dispatcher는 중첩 도구 호출에 필요하다.

hook 정의와 ALLOW/DENY 응답을 preflight로 검사한다. 운영자가 소스를 검토한 자동화에만
`--reviewed-hook`을 사용한다. 내부적으로 사용하는 `--dangerously-bypass-hook-trust`는
그 세션의 hook 신뢰 확인만 생략한다. sandbox/approval 우회 flag는 사용하지 않았다.
다른 CLI 버전이나 추가 project `.codex/config.toml`은 별도 검토 전 launcher가 거부한다.

## 관찰한 실패

- `probe-native-01`: 공식 설정 문서의 `tools.view_image`가 설치 버전 strict-config에서 거부됨.
  설치 CLI가 지원하는 `features.view_image=false`를 사용했다.
- `probe-native-02`: code-mode host까지 끄면 Guard 도구 호출도 실패함. dispatcher를 복구했다.
- `probe-native-03`: 실제 정상 연결과 native 거부를 확인했다.

원본 증거: `.guard-runs/live-smoke-01`, `.guard-runs/probe-native-01`~`03`.
최종 검사와 portable evidence는 [002 전체 기록](002-live-dogfooding.md)에 연결한다.

설정 근거: [공식 Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference),
[공식 Hooks](https://learn.chatgpt.com/docs/hooks). 문서와 설치 binary가 다르면 실제 strict-config 결과를 우선 기록했다.
