# 001 MVP Implementation Plan

## 목표

Filesystem, Shell, Git 세 종류의 tool call에 대해 deterministic policy enforcement를 적용하고, ALLOW / REQUIRE_APPROVAL / DENY가 실제 실행 경계에서 동작하는 최소 제품을 만든다.

## 구현 순서

### 1. Core Domain

구현:

- ToolRequest
- NormalizedAction
- PolicyDecision
- PolicyRule
- PolicyContext
- AuditEvent

완료 조건:

- 외부 I/O 없이 policy unit test 가능

### 2. Policy Engine

구현:

- rule matching
- precedence
- default deny
- rule id / reason

테스트:

- explicit deny가 allow보다 우선
- approval이 allow보다 우선
- unknown action은 deny

### 3. Filesystem Adapter

구현:

- canonical workspace
- path normalization
- sensitive path classifier
- read/write/delete executor

테스트:

- traversal
- symlink escape
- non-existent path
- secret path
- policy path

### 4. Shell Adapter

구현:

- structured command request
- executable/argv/cwd normalization
- project command allowlist
- unsafe composition detection

테스트:

- normal test command
- unknown command
- chaining
- nested shell
- redirection

### 5. Git Adapter

구현:

- status/diff/log
- add/commit
- push
- force detection
- branch/remote state

테스트:

- read-only ALLOW
- commit policy
- push APPROVAL
- force push DENY

### 6. Approval Manager

구현:

- pending approval
- normalized action digest
- expiry
- run/workspace/policy binding
- recheck before execute

테스트:

- exact approval
- argument substitution
- replay
- expiry
- state change

### 7. Audit

구현:

- structured local log
- redaction
- decision/execution linking
- policy version

테스트:

- normal record
- denied record
- secret redaction

### 8. Agent Integration

처음에는 하나의 coding agent만 연결한다.

원칙:

- Agent 종류보다 gateway 경계가 핵심
- Agent가 executor를 직접 호출하지 못함
- DENY와 APPROVAL 결과를 Agent가 이해 가능한 형태로 반환

### 9. Dogfooding

실제 repository에서 작은 작업부터 사용한다.

첫 대상:

- test 추가
- 작은 bug fix
- refactor

정책이 작업을 과도하게 막거나 너무 넓게 허용하면 기록 후 수정한다.

## Test-First 규칙

각 stage는 다음 순서로 진행한다.

~~~text
문서의 expected behavior 확인
→ 실패하는 test 작성
→ 최소 구현
→ focused test
→ adversarial/regression test
→ full suite
→ docs/exec 기록
~~~

새로운 우회나 실패를 발견했을 때 바로 구현부터 고치지 않는다.

먼저 재현 test를 만든다.

## 구현하지 않을 것

001에서 하지 않는다.

- multi-agent
- browser
- DB
- cloud deploy
- network egress control
- production IAM
- UI dashboard
- LLM 기반 policy classifier
- 복잡한 policy DSL

## 001 Exit Criteria

- 기본 22개 이상의 scenario가 자동화
- 전체 suite pass
- 실제 temp repo integration pass
- 실제 coding task 최소 1건 수행
- approval 없이 remote side effect 없음
- docs/exec/001-mvp.md 작성
